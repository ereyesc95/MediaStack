1. WHAT THIS PROJECT IS
================================================================================

Modern reimplementation of **MediaBinger** — personal media library + player for:
  Music, Series, Movies, Books, Games, Universes.

Reads files from a media root on disk, enriches with a legacy SQL dump / SQLite DB,
serves a FastAPI API + React SPA.

Stack:
  - Backend: FastAPI + Uvicorn + SQLAlchemy + Pydantic Settings (Python 3.11+)
  - Frontend: React 19 + Vite 6 + TypeScript (no router library — custom route helpers)
  - DB: SQLite by default (data/mystack.db); optional MySQL import
  - Default API port: 8766
  - Default Vite port: 5174 (proxies /api → 8766)

3. REQUIREMENTS / SETUP (NEW MACHINE)
================================================================================

Prerequisites:
  - Python 3.11+ (3.14 tested)
  - Node.js 18+ and npm
  - Optional Chrome (run.py can auto-open)
  - A media library root containing Music/, Series/, Movies/, Books/, Games/

Install:
  pip install -r backend/requirements.txt
  cd frontend && npm install

First-time DB (from project root):
  python run.py --import-sql --import-replace
  Source dump: data/databinger.sql (legacy MediaBinger schema)

Daily dev — TWO terminals:
  Terminal 1 (API):   python run.py          → http://127.0.0.1:8766
  Terminal 2 (UI):    cd frontend && npm run dev → http://localhost:5174

Common mistake: stopping the API before starting Vite. Keep both running.
If UI says “Cannot reach the API”, Terminal 1 is down or port 8766 blocked.

Production-style: npm run build in frontend/, then python run.py serves frontend/dist.

Optional hosts entry:
  127.0.0.1 mystack
  Then http://mystack:5174 (Vite allowedHosts includes mystack).

6. ARCHITECTURE SUMMARY
================================================================================

MUSIC is artist-centric:
  Music/{Letter}/{Artist}/Albums|Singles|…   (preferred)
  Legacy: Music/{Letter}/{Artist}/Audio/{Category}/
  Also: Video/, Library/, Gallery/, Tours/

MOVIES / SERIES / BOOKS / GAMES use franchise/work folder names as the cross-module key.
  Same {Franchise} folder name across modules → Related media (franchise index).
  Exceptions: .path sidecars, symlinks, future franchise_overrides.json.
  Music artist name ≠ movie franchise (e.g. HIM vs Elvis biopic) — needs subject/DB links later.

Routing:
  Custom push*Route helpers + history; dual-parse legacy IDs/hashes AND human-readable slugs.
  Pass display titles into push*Route when possible so slug URLs appear immediately.

Profiles / admin:
  Multi-profile support; admin password gates write/tag/fetch tools.
  NSFW gating (admin NSFW password separate).

Playback:
  Mini audio player shared across release / playlist / event setlist pages.
  Media URLs: /api/media/file?path=…&v={mtime}  (cache-buster after extension!)

7. LIBRARY LAYOUT RULES (LOCKED — DO NOT CHANGE LIGHTLY)
================================================================================

Letter tier: first letter of grouping title (H/ = HIM). Use # for non-alpha.
Date folders: {YYYY.MM.DD}. {Title} or {YYYY}. {Title}
Special chars in DB names: █ → '   ■ → ,
Franchise slug: casefold + whitespace normalize; aliases off by default.

Seasons (Series): {YYYY.MM.DD}. Season N/ under show/subseries — NO Seasons/ wrapper
  (docs may still mention older patterns; prefer AGENTS.md + layout doc current text)

Movies: always {Work}/{date}. {Film}/ — never leave the feature file at work root.

Cross-media: franchise index Related panel — no nested portal farms inside modules.

Series audio: …/[Audio]/{Albums|…}/ with .lnk shortcuts into Music releases.

Golden path fixture: Series/D/Dragon Ball/ (+ Movies/Books/Games scaffolding)

Music audio categories: Albums, Extended Plays, Compilations, Demos, Live Albums, Soundtracks, Singles
  (Demos: tab after Compilations; Collection type "Demo"; excluded from Appears on / Taken from;
   never preferred over studio for cover/title match)
Box set: folder tag [Box Set] on compilations with .lnk sections.

Editions: sibling folders under release (Standard Edition preferred default).
Format versions: CD / LP / Digital sibling folders (≥2); each has own [Artwork].
Discs/sides/tapes: Disc N/, Side A/, Tape/, or flat A1./B1. vinyl naming.

8. ARTWORK STEMS (CRITICAL FOR MUSIC PLAYBACK UI)
================================================================================

Code truth: backend/app/artwork_stems.py

Album / edition motion (hard cut — these exact stems):
  Cover - Animation   (.mp4/.webm/.mov/.m4v)  → cover_animation_url
  Cover - Canvas      (.mp4/.webm/.mov/.m4v)  → canvas_url

Static:
  Cover - Front / Cover - Album
  Cover - Back / Inner / Banner / Landscape / Portrait
  Disc, Disc 01, …

Track-specific:
  Cover - {Track Title}       still — OVERRIDES album front for that track
  Animation - {Track Title}   track motion video
  Canvas - {Track Title}      track canvas video

Photocards / photos:
  Photocard - Portrait - Front (and Back / Landscape variants; legacy aliases exist)
  Photo - Portrait / Landscape / Square / Banner  (gallery + fallbacks)
  Code - Spotify / Code - QR

PRIORITY FOR NOW-PLAYING COVER SLOT (must preserve):
  1. Track Animation - {title} if present
  2. Else if track has own still (Cover - {title} OR linked single Cover - Front):
       show STILL; suppress album Cover - Animation / Cover - Canvas
  3. Else album Cover - Animation (video) over Cover - Front
  Linked singles: album track that also exists under Singles/… uses single artwork
  (see release_playback_art.playback_art_for_audio_file / apply_track_artwork_overrides).

Frontend gotcha (fixed Oct 2026 — do not reintroduce):
  ReleaseTracklist trackArt() must NOT do:
    track.cover_animation_url ?? edition.cover_animation_url
  when the track has its own cover URL different from the edition.
  Intentional null means “suppressed”; ?? would resurrect album animation.

Video URL detection gotcha (fixed Oct 2026):
  Media URLs look like: …Cover%20-%20Animation.mp4&v=123456
  Extension is followed by & not ? or EOS.
  Use frontend/src/isVideoMediaUrl.ts:
    /\.(mp4|webm|mov|m4v)(?:$|[?#&])/i
  Do not use /(\?|$)/ only — animation/canvas will never play.

17. KNOWN PITFALLS
================================================================================

1. Video regex missing & after .mp4 → animation never plays.
2. ?? fallback from track null → edition animation overrides single/track still.
3. Setlist cover size using % → collapses to 0; use rem.
4. QR/Spotify codes row: flex height:0 tricks; prefer grid fr tracks.
5. Stale overview/tracklist caches after API field changes.
6. Stopping API while developing UI → mysterious empty states.
7. README may say "Animation - Album"; code uses "Cover - Animation" for album motion.
8. Track title stems strip bracket suffixes and trailing (parens) before matching files.
